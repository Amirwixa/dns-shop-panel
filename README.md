# 🌐 DNS Shop Panel — SmartDNS شبه‌شکن + پنل مدیریت فارسی

پروژه‌ای **سبک و کم‌مصرف** برای فروش سرویس **DNS رفع تحریم (دقیقاً مثل شکن / شلتر / الکترو)** به کاربران.
هر کاربر با **IP عمومی** خودش ثبت می‌شود و تا تاریخ انقضا می‌تواند از سرویس استفاده کند.
IPهای ناشناس یا منقضی‌شده خودکار **رد** می‌شوند.

## 🚀 نصب با یک دستور

روی سرور اوبونتو (root):

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/Amirwixa/dns-shop-panel/main/install-remote.sh)
```

- سرور تازه → نصب کامل خودکار (DNS + پروکسی + پنل)
- سروری که پنل را دارد → آپدیت خودکار، بدون از دست رفتن کاربران
- جزئیات انتشار روی گیت‌هاب: فایل [`PUSH_TO_GITHUB.md`](PUSH_TO_GITHUB.md)

## 🔀 چطور مثل شکن کار می‌کند؟

```
کاربر عادی (google.com)          دامنه تحریمی (binance.com / openai.com)
        │                                    │
        ▼                                    ▼
  DNS → IP واقعی گوگل              DNS → IP سرور شما
        │                                    │
        ▼                                    ▼
  اتصال مستقیم                     اتصال به سرور شما (پورت 443/80)
                                  پروکسی SNI → اتصال به سایت واقعی با IP خارجی
                                  ✅ سایت مقصد IP ایرانی نمی‌بیند → تحریم دور می‌خورد
```

- ✅ فقط ترافیک **دامنه‌های لیست پروکسی** از سرور شما عبور می‌کند؛ بقیه مستقیم وصل می‌شوند (مثل شکن، سرعت بالا)
- ✅ سایت‌های تحریمی، IP **خارجی سرور شما** را می‌بینند → تحریم/محدودیت جغرافیایی اعمال نمی‌شود
- ✅ لیست دامنه‌ها از قبل پر شده (بایننس، OpenAI، AWS، داکر و...) و از پنل قابل ویرایش است

> ⚠️ **صادقانه بگویم:** این مدل (مثل خود شکن) برای **رفع تحریم** است — یعنی سایت‌هایی که *خودشان* ایرانی‌ها را بلاک می‌کنند.
> سایت‌هایی که *داخل ایران فیلترند* (مثل X، یوتیوب...) با DNS تنها باز نمی‌شوند چون فیلترینگ روی SNI هم اعمال می‌شود؛ آن‌ها VPN می‌خواهند.

- دسترسی root + IP عمومی ثابت

## 🚀 نصب (۵ دقیقه)

**۱. آپلود پروژه روی سرور:**

```bash
# روی سیستم خودت (پوشه پروژه را زیپ/آپلود کن) یا مستقیم روی سرور:
scp -r dns-shop-panel root@SERVER_IP:/root/
ssh root@SERVER_IP
cd /root/dns-shop-panel
```

**۲. اجرای نصب:**

```bash
chmod +x install.sh
sudo bash install.sh
```

نصاب از شما می‌پرسد:
- 🔌 پورت پنل (پیش‌فرض `8080` — هر پورت دلخواهی بده)
- 👤 نام‌کاربری و 🔑 رمز مدیر
- 🌐 آپ‌استریم‌ها (پیش‌فرض `8.8.8.8` و `1.1.1.1`)
- 🔓 پورت‌های اضافه برای باز نگه داشتن در فایروال (اگه روی سرور تانل یا سرویس دیگه‌ای داری، مثلاً `9003 8080 7777` — چون نصاب UFW را فعال می‌کند و بدون این، آن سرویس‌ها قطع می‌شوند!)

نصاب خودکار انجام می‌دهد:
- ✅ نصب پایتون و وابستگی‌ها
- ✅ آزادسازی پورت 53 (رفع تداخل با systemd-resolved)
- ✅ راه‌اندازی سرویس DNS روی پورت 53 (UDP + TCP)
- ✅ راه‌اندازی وب‌پنل روی پورت دلخواه (سرویس systemd + auto-restart)
- ✅ تنظیم فایروال (UFW)

**۳. ورود به پنل:**

```
http://SERVER_IP:8080
```

## 👥 ساخت اکانت برای مشتری (روش کار)

1. از مشتری بخواه **IP عمومی** خودش را بفرستد (مثلاً با جستجوی «my ip» در گوگل).
2. در پنل ← **کاربران** ← **➕ کاربر جدید**:
   - نام، IP، مدت اعتبار (روز)، توضیحات
3. **IP سرور** را به مشتری بده تا به‌عنوان DNS روی دستگاهش ست کند:

| دستگاه | مسیر |
|---|---|
| 🤖 اندروید | Wi-Fi ← Modify ← IP Settings روی Static ← DNS 1 = IP سرور |
| 🍎 آیفون | Wi-Fi ← ⓘ ← Configure DNS روی Manual ← IP سرور |
| 🪟 ویندوز | Adapter ← IPv4 ← Use the following DNS ← IP سرور |
| 🎮 پلی‌استیشن/ایکس‌باکس | Network ← DNS Manual ← IP سرور |

4. تست از سمت مشتری (بعد از ثبت IP او در پنل):
```bash
nslookup google.com SERVER_IP     # باید IPهای واقعی گوگل را بدهد (مستقیم)
nslookup binance.com SERVER_IP    # باید IP خود سرور را بدهد (پروکسی 🔀)
```
بعد سایت تحریمی (مثلاً binance.com) را در مرورگر باز کند — باید بدون خطای تحریم باز شود.

> ⏳ بعد از **انقضا**، کاربر خودکار رد می‌شود و در پنل با برچسب «منقضی» مشخص است.
> با دکمه ⏳ می‌توانی تمدیدش کنی.

## 🎚️ حالت هوشمند / کامل

از صفحه **⚙️ تنظیمات DNS** می‌توانی حالت سرویس را انتخاب کنی:

| حالت | رفتار |
|---|---|
| 🧠 **هوشمند** (پیش‌فرض، مثل شکن) | فقط دامنه‌های «لیست پروکسی» از سرور عبور می‌کنند؛ بقیه مستقیم. مصرف کمتر، سرعت بیشتر. |
| 🌐 **کامل** (تمام دستگاه) | **همه** دامنه‌ها به IP سرور برمی‌گردند و کل وب‌گردی مشتری از سرور رد می‌شود — بدون نیاز به هیچ لیستی. |

**نکات حالت کامل:**
- ✅ بلاک‌لیست و رکوردهای اختصاصی همچنان کار می‌کنند. نام‌های شبکه داخلی (`localhost`، `.local`، تک‌اسمی‌ها و...) خودکار مستثنی‌اند.
- ⚠️ پهنای باند و CPU بیشتری مصرف می‌شود (همه وب‌گردی رله می‌شود).
- ⚠️ اپ‌های غیر وب (بازی‌های UDP، تماس صوتی/تصویری، ایمیل، SSH و...) ممکن است کار نکنند — این محدودیت ذاتی DNS است، نه باگ؛ فقط VPN واقعی آن‌ها را پوشش می‌دهد.

## 🔗 لینک ثبت خودکار IP (مهم!)

چون IP اینترنت موبایل/خانگی مدام عوض می‌شود، هر کاربر موقع ساخت اکانت یک **لینک اختصاصی** هم می‌گیرد:

```
http://SERVER_IP:PANEL_PORT/u/توکن_غیرقابل_حدس
```

**روش کار:**
1. موقع ساخت کاربر، پنل خودکار لینک را نشان می‌دهد — آن را برای مشتری بفرست (بعداً هم با دکمه 🔗 جلوی هر کاربر می‌بینی).
2. مشتری لینک را باز می‌کند → IP فعلی خودش + IP ثبت‌شده را می‌بیند → دکمه **«ثبت IP فعلی من»** را می‌زند → تمام!
3. هر وقت اینترنتش عوض شد (وای‌فای ↔ موبایل)، دوباره همین لینک را باز می‌کند — **دیگر لازم نیست به تو پیام بدهد.**

**نکات:**
- ⚠️ به مشتری بگو لینک را با همان اینترنتی باز کند که می‌خواهد DNS با آن کار کند.
- 🔒 باز کردن لینک به‌خودی‌خود چیزی را عوض نمی‌کند (پیش‌نمایش تلگرام و... امن است)؛ فقط با زدن دکمه ثبت می‌شود.
- ♻️ اگر لینک لو رفت، با دکمه «لینک جدید» عوضش کن (قبلی خودکار باطل می‌شود).
- ⏳ حداقل فاصله بین دو ثبت (ضد سوءاستفاده) از تنظیمات DNS قابل تغییر است (پیش‌فرض ۶۰ ثانیه).
- 👨‍👩‍👧 اگر چند مشتری پشت یک مودم/اینترنت مشترک‌اند (یک IP)، مشکلی نیست — IP مشترک پشتیبانی می‌شود.
- 🤖 برای اتوماسیون (اسکریپت/روتر) به‌جای مرورگر:
  ```bash
  curl -X POST "http://SERVER_IP:PANEL_PORT/u/TOKEN" -H "Accept: application/json"
  ```

## 🔧 دستورات مدیریتی

```bash
# وضعیت سرویس‌ها
systemctl status dns-smart dns-panel

# لاگ زنده DNS و پنل
journalctl -u dns-smart -f
journalctl -u dns-panel -f

# ری‌استارت
systemctl restart dns-smart dns-panel

# تغییر پورت پنل
bash /root/dns-shop-panel/change-port.sh

# حذف کامل
bash /root/dns-shop-panel/uninstall.sh

# بکاپ دستی دیتابیس
cp /opt/dns-panel/data/panel.db ~/backup-$(date +%F).db
```

## ⚙️ معماری فنی

```
  دامنه عادی:  مشتری ──▶ SmartDNS :53 ──▶ IP واقعی ──▶ اتصال مستقیم
  دامنه تحریمی: مشتری ──▶ SmartDNS :53 ──▶ IP سرور شما
                                              │
                                              ▼
                                    SNI Proxy :80/:443
                                    (تشخیص SNI/Host)
                                              │
                                              ▼
                                    سایت واقعی (با IP خارجی سرور)
                                                  ✅ تحریم دور خورد

  مدیریت:      Web Panel :8080 (قابل تغییر) — Flask + SQLite + Waitress
```

- **دیتابیس:** SQLite (WAL mode) در `/opt/dns-panel/data/panel.db` — بدون نیاز به MySQL
- **مصرف رم:** حدود ۵۰–۱۰۰ مگابایت در حالت عادی
- **اعمال تنظیمات DNS:** حداکثر ۳۰ ثانیه بعد، بدون ری‌استارت

## 🔒 نکات امنیتی مهم

1. ✅ حتماً گزینه **«رد IPهای ناشناس»** روشن بماند (در غیر این صورت ریزالور باز می‌شوی و سوءاستفاده می‌شود).
2. ✅ رمز مدیر قوی بگذار و پورت پنل را عددی غیرحدسی انتخاب کن (مثلاً `20534`).
3. ✅ سرور را آپدیت نگه دار: `apt update && apt upgrade`
4. ⚠️ این سرویس **SmartDNS** است نه VPN — ترافیک را رمزنگاری نمی‌کند، بلکه مسیر DNS را از خارج ایران عبور می‌دهد و دسترسی به سرویس‌های تحریمی/فیلترشده در سطح DNS را باز می‌کند.
5. ⚠️ لاگ‌ها شامل دامنه‌های بازدیدشده کاربران است — حریم خصوصی مشتریان را رعایت کن.

|---|---|
| 🩺 اول از همه | `sudo bash doctor.sh` را اجرا کن — دقیق می‌گوید کدام بخش قرمز است |
| بعد از آپدیت هیچ سایتی باز نمی‌شود | معمولاً یکی از این‌هاست: ۱) حالت کامل فعال است ولی `dns-sni` بالانیست (پورت ۸۰/۴۴۳ اشغال) → برگرد به هوشمند یا پورت را آزاد کن ۲) `server_ip` اشتباه است (پنل → تنظیمات DNS) ۳) IP مشتری عوض شده → لینک 🔗 را باز کند |
| پورت ۸۰/۴۴۳ اشغال است (تداخل با تانل/وب‌سرور دیگر) | `ss -tlnp \| grep -E ':80\|:443'` بزن ببین کی گرفته؛ یا آن سرویس را به پورت دیگر منتقل کن یا قید پروکسی رفع تحریم را بزن (فقط DNS ساده + هوشمند برای دامنه‌های عادی کار می‌کند) |
| تانل/سرویس دیگرم بعد از نصب قطع شد | نصاب UFW را فعال می‌کند — پورت تانلت را باز کن: `ufw allow 1234/tcp` (و udp اگر لازم است) بعد `ufw reload` |
| مشتری «رد» می‌شود ولی IP درست است | IP مشتری عوض شده (اینترنت موبایل/ADSL داینامیک) — لینک 🔗 اختصاصی‌اش را باز کند و دکمه ثبت را بزند |
| پورت 53 اشغال است | `ss -lunp \| grep :53` بزن و سرویس مزاحم (named/dnsmasq) را stop/disable کن |
| پنل بالا نمی‌آید | `journalctl -u dns-panel -e` را ببین؛ احتمالاً پورت تکراری است |
| کوئری کند است | آپ‌استریم نزدیک‌تر انتخاب کن یا کش را فعال کن |
